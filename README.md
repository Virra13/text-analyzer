# Text Analyzer

Консольное приложение на Java и Spring Boot для построения частотного словаря по материалу `.txt`-файлов указанной директории. 

Приложение поддерживает последовательный и многопоточный режимы обработки, позволяет сравнивать их производительность и сохранять результат в консоль или JSON.

## Возможности

Приложение:

* читает все `.txt`-файлы из указанной папки;
* поддерживает последовательную и многопоточную обработку файлов;
* позволяет задавать количество потоков для многопоточного режима;
* подсчитывает количество вхождений слов;
* не учитывает регистр и знаки препинания;
* игнорирует слова короче заданной длины;
* поддерживает файл со стоп-словами;
* объединяет результаты анализа всех успешно обработанных файлов;
* выводит время выполнения анализа;
* выводит количество успешно обработанных файлов;
* выводит результат в консоль или сохраняет его в JSON.

## Особенности обработки

* Анализируются только `.txt`-файлы, расположенные непосредственно в указанной папке. Вложенные директории не обходятся.
* Файлы читаются в кодировке UTF-8.
* Словом считается последовательность букв Unicode. Внутри слова допускаются дефис, подчёркивание и апостроф, например: `кто-то`, `don't`, `слово_слово`.
* Цифры и остальные символы не входят в состав слова.
* Регистр не учитывается: `Java`, `JAVA` и `java` считаются одним словом.
* Стоп-слова обрабатываются по тем же правилам и также не зависят от регистра.
* Слова сортируются по убыванию количества вхождений. При одинаковой частоте используется сортировка по алфавиту.
* Если отдельный файл невозможно прочитать, он пропускается, а информация об ошибке добавляется в результат.
* При отсутствии подходящих слов приложение выводит пустой результат.
* При записи в JSON родительская директория должна уже существовать. Существующий файл результата перезаписывается.
* Минимальная длина слова и количество слов в результате должны быть 1 или больше.
* Если в переданной директории нет подходящих `.txt`-файлов, приложение завершает анализ с пустым результатом.

## Режимы обработки

Приложение поддерживает два режима:

`single` — последовательная обработка файлов в одном потоке.

`multi` — параллельная обработка файлов через фиксированный пул потоков `ExecutorService`.

В многопоточном режиме для каждого файла создаётся отдельная задача. Файл читается и анализируется внутри задачи, после чего локальный результат объединяется с результатами остальных файлов.

Промежуточные результаты отдельных задач не используют общую изменяемую структуру данных. Объединение выполняется после завершения задач, что позволяет избежать конфликтов при одновременной обработке файлов.

## Структура проекта

- `cli` — обработка параметров командной строки;
- `application` — координация сценария анализа;
- `input` — чтение текстовых файлов и стоп-слов;
- `processing` — последовательная и многопоточная стратегии обработки файлов;
- `analyzer` — извлечение и подсчёт слов;
- `output` — вывод в консоль и JSON;
- `model` — модели результатов;
- `exception` — исключения приложения.
  
## Требования

- Java 17+
- Maven 3.9+
  
## Сборка

```bash
.\mvnw.cmd clean package
```

После сборки исполняемый JAR-файл будет находиться в директории `target`.

### Запуск и тестовые данные

В репозитории находятся две папки с текстами.

`texts` содержит небольшие .txt-файлы для проверки корректности анализа.

`texts-large` содержит более объёмные текстовые файлы для сравнения последовательного и многопоточного режимов.

Также имеется папка `config` с файлами стоп-слов:

`stopwords-for-texts.txt` предназначен для обычного набора texts.

`stopwords-for-large-texts.txt` используется для большого набора texts-large.

### Параметры

| Параметр       | Описание                             | Обязательный |
| -------------- |--------------------------------------| ------------ |
| `--dir`        | Путь к папке с `.txt`-файлами        | Да           |
| `--min-length` | Минимальная длина учитываемого слова | Да           |
| `--top`        | Количество слов в результате         | Да           |
| `--stopwords`  | Путь к файлу со стоп-словами         | Нет          |
| `--output`     | Путь к JSON-файлу с результатом      | Нет          |
| `--mode`       | Режим обработки: single или multi    | Нет          |
| `--threads`    | Количество потоков для режима multi  | Нет          |
| `--help`       | Показать справку                     | Нет          |

## Примеры запуска

Последовательная обработка небольшого набора:

```bash
java -jar target/text-analyzer.jar --dir=./texts --min-length=3 --top=10 --mode=single
```
Многопоточная обработка небольшого набора в 4 потока:

```bash
java -jar target/text-analyzer.jar --dir=./texts --min-length=3 --top=10 --mode=multi --threads=4
```

Последовательная обработка небольшого набора с использованием стоп-слов:

```bash
java -jar target/text-analyzer.jar --dir=./texts --min-length=5 --top=10 --stopwords=./config/stopwords.txt
```

Последовательная обработка больших текстов с минимальной длиной слова 5 и стоп-словами с сохранением результата в JSON:

```bash
java -jar target/text-analyzer.jar --dir=./texts-large --min-length=5 --top=10 --mode=single --stopwords=./config/stopwords-for-large-texts.txt --output=./results.json
```

Многопоточная обработка тех же файлов в 4 потока:

```bash
java -jar target/text-analyzer.jar --dir=./texts-large --min-length=5 --top=10 --mode=multi --threads=4 --stopwords=./config/stopwords-for-large-texts.txt --output=./results.json
```

Просмотр справки:

```bash
java -jar target/text-analyzer.jar --help
```

## Использованный подход

Приложение разработано на Java 21 с использованием Spring Boot для организации компонентов и внедрения зависимостей. Для сборки используется Maven. Работа с JSON реализована через Jackson, логирование — через SLF4J, сокращение шаблонного кода — через Lombok. Для тестирования используются JUnit 5 и Mockito. Многопоточная обработка реализована средствами Java Concurrency API: `ExecutorService` и `Future`.

Для обработки файлов используются две стратегии: последовательная и многопоточная. Они реализуют общий интерфейс `AnalysisProcessor`, а необходимая стратегия выбирается в зависимости от параметра `--mode`. Это позволяет отделить способ выполнения анализа от основной логики приложения и при необходимости добавлять новые варианты обработки без изменения `ApplicationService`.

В режиме multi используется фиксированный пул потоков ExecutorService. Для каждого найденного файла создаётся отдельная задача, внутри которой выполняются чтение и анализ файла. Такой вариант выбран потому, что он напрямую соответствует требованиям приложения: количество рабочих потоков можно явно ограничить параметром --threads, а сами потоки переиспользуются для обработки нескольких файлов. По сравнению с ручным созданием Thread это упрощает управление потоками и не позволяет их количеству бесконтрольно расти вместе с числом файлов. Более сложные инструменты вроде CompletableFuture, ForkJoinPool или parallelStream здесь не дают существенных преимуществ: обработка каждого файла представляет собой независимую законченную задачу без цепочек асинхронных действий и рекурсивного разбиения, а фиксированный ExecutorService делает размер пула и порядок работы приложения наиболее явными и предсказуемыми.

Каждая задача формирует собственный локальный словарь частот и возвращает его как результат выполнения, после чего результаты объединяются в основном потоке. Такой способ выбран вместо общей ConcurrentHashMap или синхронизации доступа к обычной коллекции, поскольку рабочим потокам не требуется совместно изменять одну структуру данных. Это уменьшает количество конкурентного доступа, исключает необходимость вручную организовывать блокировки и делает логику объединения результатов проще для чтения и тестирования. 

Решение масштабируется по количеству обрабатываемых файлов: при увеличении их числа задачи распределяются между потоками фиксированного пула, а размер пула можно задавать через `--threads` в зависимости от доступных ресурсов. При этом количество потоков не растёт вместе с количеством файлов, поэтому большое число входных файлов не приводит к созданию такого же числа потоков. Архитектура также позволяет добавить другую реализацию `AnalysisProcessor`, например обработку с другим способом распределения задач, не изменяя остальные компоненты приложения. 

Функциональность анализа также можно расширять независимо от механизма обработки: добавлять новые правила выделения слов, другие способы фильтрации, дополнительные статистики и форматы результата.
