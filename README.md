# Text Analyzer

Учебный проект, созданный для демонстрации поэтапного развития приложения с сохранением существующей архитектуры и разделения ответственности между компонентами.

Основная цель проекта — демонстрация, как простое приложение может последовательно расширяться новыми требованиями без полного переписывания уже существующей логики. При разработке использовались Dependency Injection, принципы SOLID, разделение на слои и стратегии обработки.

Разработка велась в несколько этапов:

1. **Консольное приложение**  
   Реализован анализ `.txt`-файлов из указанной директории, фильтрация слов, поддержка стоп-слов, вывод результата в консоль или JSON.

2. **Многопоточная обработка**  
   К существующему приложению добавлены `single`- и `multi`-режимы. Параллельная обработка файлов реализована через `ExecutorService`, при этом логика многопоточности изолирована от основной логики анализа.

3. **REST-сервис**  
   Приложение расширено REST API для асинхронного запуска анализов и получения результатов. Добавлены Spring Security, Spring Data JPA, хранение результатов и истории запусков в базе данных, статусы выполнения и аудит пользователей.

При переходе между этапами основная логика анализа текстов не заменялась REST- или многопоточной реализацией. Новые возможности добавлялись отдельными слоями и компонентами поверх существующей функциональности. CLI и REST используют общие сервисы и модели анализа, а различающаяся инфраструктура разделена с помощью Spring Profiles.

Историю развития проекта можно проследить по веткам и Pull Request / Merge Request: изменения каждого этапа добавлялись отдельно, что позволяет увидеть переход от первоначального однопоточного консольного приложения к многопоточной версии, а затем к REST-сервису с сохранением исходной структуры проекта.

Проект носит демонстрационный характер. Решения, связанные с тестовыми пользователями, настройкой H2 и доступом к H2 Console, намеренно упрощены для локального запуска и демонстрации функциональности и не предназначены для production-использования.
