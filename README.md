# Text Analyzer

Приложение на Java и Spring Boot для построения частотного словаря по материалу `.txt`-файлов указанной директории.

Приложение поддерживает два способа запуска:
- CLI-режим для локального анализа файлов с выводом результата в консоль или JSON;
- REST-режим для асинхронного запуска анализов через API с сохранением результатов в базе данных.

Анализ может выполняться последовательно или многопоточно.

## Возможности

Приложение:

* анализирует .txt-файлы и строит частотный словарь;
* поддерживает single- и multi-режимы обработки;
* поддерживает запуск анализа через REST API;
* учитывает минимальную длину слова и стоп-слова;
* в CLI-режиме выводит результат в консоль или сохраняет его в JSON;
* в REST-режиме возвращает результат через API и сохраняет его в базе данных;
* сохраняет историю, результаты и ошибки анализов в базе данных;
* ограничивает доступ к REST API через Spring Security;
* хранит данные о пользователе и параметрах запуска анализа.

## Особенности обработки

* Анализируются только `.txt`-файлы, расположенные непосредственно в указанной папке. Вложенные директории не обходятся.
* Файлы читаются в кодировке UTF-8.
* Словом считается последовательность букв Unicode. Внутри слова допускаются дефис, подчёркивание и апостроф, например: `кто-то`, `don't`, `слово_слово`.
* Цифры и остальные символы не входят в состав слова.
* Регистр не учитывается: `Java`, `JAVA` и `java` считаются одним словом.
* Стоп-слова обрабатываются по тем же правилам и также не зависят от регистра.
* Слова сортируются по убыванию количества вхождений. При одинаковой частоте используется сортировка по алфавиту.
* Если отдельный файл невозможно прочитать, он пропускается, а информация об ошибке добавляется в результат.
* При отсутствии подходящих слов приложение выводит пустой результат.
* При записи в JSON родительская директория должна уже существовать. Существующий файл результата перезаписывается.
* Минимальная длина слова и количество слов в результате должны быть 1 или больше.
* Если в переданной директории нет подходящих `.txt`-файлов, приложение завершает анализ с пустым результатом.

## Структура проекта


- `cli` — обработка параметров командной строки и запуск CLI-сценария;
- `analysis.application` — координация выполнения анализа и конфигурация;
- `analysis.processing` — последовательная и многопоточная стратегии обработки файлов;
- `analysis.model` — модели результатов анализа;
- `input` — поиск и чтение текстовых файлов и стоп-слов;
- `analyzer` — извлечение и подсчёт слов;
- `output` — вывод результата в консоль и JSON;
- `api.controller` — REST-контроллеры;
- `api.dto` — модели REST-запросов и ответов;
- `api.service` — управление запуском, состоянием и сохранением анализов;
- `api.mapper` — преобразование сущностей БД в REST-модели;
- `persistence.entity` — JPA-сущности;
- `persistence.repository` — Spring Data JPA-репозитории;
- `security` — Spring Security, пользователи и авторизация;
- `exception` — исключения и глобальная обработка ошибок REST.

## Требования

- Java 17+
- Maven 3.4+ (Maven Wrapper входит в проект)
  
## Сборка

```bash
.\mvnw.cmd clean package
```

После сборки исполняемый JAR-файл будет находиться в директории `target`.

## Режимы запуска приложения

По умолчанию приложение запускается как консольное.

REST-сервис запускается через Spring-профиль `rest`.

### Запуск и тестовые данные

В репозитории находятся две папки с текстами.

`texts` содержит небольшие .txt-файлы для проверки корректности анализа.

`texts-large` содержит более объёмные текстовые файлы для сравнения последовательного и многопоточного режимов.

Также имеется папка `config` с файлами стоп-слов:

`stopwords-for-texts.txt` предназначен для обычного набора texts.

`stopwords-for-large-texts.txt` используется для большого набора texts-large.

### Параметры

| Параметр       | Описание                             | Обязательный |
| -------------- |--------------------------------------| ------------ |
| `--dir`        | Путь к папке с `.txt`-файлами        | Да           |
| `--min-length` | Минимальная длина учитываемого слова | Да           |
| `--top`        | Количество слов в результате         | Да           |
| `--stopwords`  | Путь к файлу со стоп-словами         | Нет          |
| `--output`     | Путь к JSON-файлу с результатом      | Нет          |
| `--mode`       | Режим обработки: single или multi    | Нет          |
| `--threads`    | Количество потоков для режима multi  | Нет          |
| `--help`       | Показать справку                     | Нет          |

## Запуск REST:

```bash
java -jar target/text-analyzer.jar --spring.profiles.active=rest
```

По умолчанию сервис доступен по адресу http://localhost:8080

Доступ к /api/** требует HTTP Basic Authentication.

### Тестовые пользователи

| Пользователь | Пароль | Роль |
|---|---|---|
| User1 | 11111 | USER |
| User2 | 22222 | USER |
| Admin | admin | ADMIN |

Пользователь с ролью `USER` получает доступ только к своим анализам. Пользователь с ролью `ADMIN` может получать список всех анализов.

### Запуск анализа

`POST /api/analyze`

Пример тела запроса:

```json
{
  "directory": "texts",
  "minWordLength": 3,
  "topCount": 10,
  "mode": "MULTI",
  "threads": 4,
  "stopWords": "config/stopwords-for-texts.txt"
}
```

При успешном создании анализа сервис возвращает 202 Accepted:
```json
{
"id": "f5d01536-3394-446a-a845-83b97ff83045",
"status": "PENDING"
}
```

### Получение анализа

`GET /api/results/{id}`

### Получение истории

`GET /api/results`

Возвращает список сохранённых анализов, доступных текущему пользователю.


## Примеры запуска CLI:

Последовательная обработка небольшого набора:

```bash
java -jar target/text-analyzer.jar --dir=./texts --min-length=3 --top=10 --mode=single
```
Многопоточная обработка небольшого набора в 4 потока:

```bash
java -jar target/text-analyzer.jar --dir=./texts --min-length=3 --top=10 --mode=multi --threads=4
```

Последовательная обработка небольшого набора с использованием стоп-слов:

```bash
java -jar target/text-analyzer.jar --dir=./texts --min-length=5 --top=10 --stopwords=./config/stopwords-for-texts.txt
```

Последовательная обработка больших текстов с минимальной длиной слова 5 и стоп-словами с сохранением результата в JSON:

```bash
java -jar target/text-analyzer.jar --dir=./texts-large --min-length=5 --top=10 --mode=single --stopwords=./config/stopwords-for-large-texts.txt --output=./results.json
```

Многопоточная обработка тех же файлов в 4 потока:

```bash
java -jar target/text-analyzer.jar --dir=./texts-large --min-length=5 --top=10 --mode=multi --threads=4 --stopwords=./config/stopwords-for-large-texts.txt --output=./results.json
```

Просмотр справки:

```bash
java -jar target/text-analyzer.jar --help
```

## Хранение данных и аудит

В REST-режиме используется база данных H2 через Spring Data JPA.

Для каждого анализа сохраняются:

- уникальный UUID;
- пользователь, запустивший анализ;
- дата и время запуска;
- параметры анализа;
- текущий статус;
- время выполнения;
- количество обработанных файлов;
- частоты слов;
- ошибки отдельных файлов;
- причина общей ошибки при статусе `FAILED`.




## Использованный подход

Приложение разработано на Java 17 с использованием Spring Boot для организации компонентов и внедрения зависимостей. Для сборки используется Maven. Работа с JSON реализована через Jackson, логирование — через SLF4J, сокращение шаблонного кода — через Lombok. Для тестирования используются JUnit 5 и Mockito.

CLI- и REST-режимы приложения разделены с помощью Spring Profiles. По умолчанию приложение запускается в консольном режиме. В этом режиме не поднимаются веб-сервер, Spring Security и JPA-инфраструктура. REST-режим запускается с профилем `rest`. В нём активируются REST API, Spring Security, работа с базой данных и асинхронное выполнение анализов. Такое разделение позволяет сохранить работу консольного приложения из предыдущих этапов и при этом независимо запускать REST-сервис.

Для обработки файлов используются две стратегии: последовательная и многопоточная. Они реализуют общий интерфейс `AnalysisProcessor`, а необходимая стратегия выбирается в зависимости от параметра `--mode`. Это позволяет отделить способ выполнения анализа от основной логики приложения и при необходимости добавлять новые варианты обработки без изменения `ApplicationService`.

Для многопоточной обработки используется Java Concurrency API (`ExecutorService`, `CompletionService`, `Future`). Каждый файл обрабатывается как независимая задача. В CLI-режиме используется фиксированный пул потоков, размер которого задаётся параметром `--threads`. Это позволяет явно ограничить количество рабочих потоков и сравнивать последовательный и многопоточный режимы. REST-сервис рассчитан на одновременный запуск нескольких анализов, поэтому использует общий `cached thread pool`. Каждый анализ при этом имеет собственное ограничение количества одновременно выполняемых файлов, определяемое параметром `threads`. Это позволяет анализам с разными настройками выполняться параллельно без создания отдельного пула для каждого запроса.

Каждая задача формирует собственный локальный словарь частот и возвращает его как результат выполнения, после чего результаты объединяются в основном потоке. Такой способ выбран вместо общей ConcurrentHashMap или синхронизации доступа к обычной коллекции, поскольку рабочим потокам вообще не требуется совместно изменять одну структуру данных. Это уменьшает количество конкурентного доступа, исключает необходимость вручную организовывать блокировки и делает логику объединения результатов проще для чтения и тестирования. Таким образом, многопоточность используется только там, где она действительно нужна — при независимом чтении и анализе файлов, а формирование итогового словаря остаётся последовательной и предсказуемой операцией.
